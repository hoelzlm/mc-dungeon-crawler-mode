# Safe Room dimensions are created by reflection at runtime

NeoForge has no public API to add a dimension while the server runs, and the Safe Room of ADR 0005 must appear on a **Crawler**'s first entry. The adapter therefore builds a `ServerLevel` itself and registers it in the private `levels` map of `MinecraftServer`, reading the private `executor` and `storageSource` fields reflectively. We accepted this over pre-registering a fixed pool of Safe Room dimensions in a datapack, which caps the number of **Crawlers**, and over a shared dimension with a plot per **Crawler**, which gives up the privacy and trivial deletion ADR 0005 chose.

Limits that follow from it. The fields are private, so a Minecraft or NeoForge update can break creation; failure is logged and the **Crawler** stays outside. A created level is not in the world's dimension registry, so it is not reloaded on server restart and a restart loses the engine's Safe Room state too (see issue #18). Creation is deferred to the end of the server tick, because adding to `levels` while the server iterates it fails. Deletion removes the level from the map, closes it and deletes its dimension folder, and logs rather than fails if any step throws.
